# UCS553 Java viva guide

ProvGuard Case Review is the course application. It takes JSONL events from the Java agent, lets a reviewer import them into SQLite, and supports opening, searching, updating and deleting cases. Import creates review rows. It leaves the original agent log untouched. The ordered-path research runner and audit CLI remain part of the same Maven reactor.

## Run the project

From the repository root, with JDK 21 and Maven 3.9:

```text
mvn clean verify
mvn -pl provguard-desktop compile javafx:run
```

The desktop module has no sibling-module runtime dependencies, so the second command runs on its own after a fresh checkout. Maven obtains OpenJFX and the SQLite JDBC driver. JavaFX UI code is in Java and uses programmatic scene construction. SQL statements use Java text blocks and JDBC bindings. Maven XML is build configuration.

The bundled `review.properties` configures the title and default database path. The launch directory determines where the default relative database file is created. Supply an alternate properties file using the JVM property `provguard.review.config` when launching the JavaFX app from an IDE. An absolute `database.path` avoids ambiguity.

## Walk through the viva demo

1. Launch Case Review. Enter a title and notes, then click **Save case**. Select the row, set **In review**, and save again.
2. Import `events.jsonl` generated by the Java agent. Import it twice. The second import skips events already in SQLite and preserves edits.
3. Search for a case, close it, then uncheck **Include closed**. Reopen the application to show persistence.
4. Select a disposable case and demonstrate the delete confirmation. Try saving an empty title to show validation.
5. For the research extension, score a recorded log with the ordered-path CLI and explain why a familiar stack can have an unfamiliar transition.

## Syllabus to code

| UCS553 topic | Where to point in the code |
| --- | --- |
| JVM, JRE, JDK, classpath, packages, Maven | JDK 21 compiles the sources via the root `pom.xml` and Maven supplies dependencies. The JVM executes the bytecode. The runtime includes the JVM and standard libraries. Explain `-cp` using the audit CLI and OpenJFX using the Maven launch. Source packages separate agent, rules, ML, and desktop. |
| Classes, objects, interfaces, abstract classes, inheritance and polymorphism | `ReviewApp` extends JavaFX `Application`. `CaseStore` is the DAO interface and `SqliteCaseStore` is its implementation. `AbstractRiskRule` provides common rule behavior. `ReviewCase` is an immutable record. |
| Access modifiers, static and instance members | Compare the private `store` and selection state in `ReviewApp` with its shared `static final LOG`; follow the public JavaFX lifecycle methods. |
| Exception hierarchy and debugging | `ReviewException` is a checked application exception and retains its cause. `ReviewCase` throws an unchecked `IllegalArgumentException` for invalid input. Break at `ReviewApp.save`, step into `SqliteCaseStore.insert`, inspect bound values, then inspect the persisted row in the test. The import dialog reports malformed JSONL line numbers. |
| ArrayList, LinkedList, HashSet, HashMap, Iterator | `SqliteCaseStore.list` accumulates rows, `ReviewApp.record` keeps a bounded recent-actions list, `EventCaseImporter.read` deduplicates UUIDs, and `ReviewApp.refresh` iterates cases to count statuses. |
| Generics, type safety and Comparator | `CaseStore` returns `List<ReviewCase>` and `Optional<ReviewCase>`. `ReviewApp.column` builds typed JavaFX columns. `ReviewApp.refresh` uses a comparator to sort by date and UUID. |
| Objects, Optional, Math, LocalDate and LocalDateTime | `ReviewCase` validates values with `Objects` and stores `LocalDateTime`. `ReviewApp` uses the date portion in its daily count. `SqliteCaseStore.find` returns `Optional`. `IsolationForestModel` uses `Math` for fitting and scoring. |
| Byte streams, character streams, file read and write | `OrderedWorkloads.serialize` uses byte-array streams. `DeserializationDemo.roundTrip` writes and reads objects using file streams. `EventCaseImporter.read` reads characters from JSONL. `OrderedPathStudy` writes reports using Java NIO. |
| Object serialization and deserialization | `SafeSerializableObject`, `ObjectOutputStream`, and `ObjectInputStream` are exercised by `DeserializationDemo` and the ordered workload. The case importer reads JSONL using Jackson and does not deserialize Java objects from uploaded files. |
| Logging and properties | `ReviewApp` uses `java.util.logging`. `ReviewSettings.load` loads bundled defaults and optional overrides with `Properties`. |
| JDBC architecture, SQLite, DriverManager, PreparedStatement, ResultSet | `SqliteCaseStore` opens a JDBC connection through the SQLite driver, binds values, and maps result rows to domain objects. |
| SELECT, INSERT, UPDATE, DELETE and transactions | `list/find`, `insert`, `update`, and `delete` provide CRUD. `importCases` commits the whole import as one transaction, rolls back on failure, and preserves user edits on repeat import. `ReviewWorkflowTest` exercises rollback using a real SQLite database. |
| Swing to JavaFX, JavaFX modules, lifecycle, scene graph | The desktop entry point uses OpenJFX `javafx-controls`, JavaFX observable controls and a `Stage` containing a `Scene`. Explain how JavaFX organizes controls as scene-graph nodes and uses property listeners. Point to `ReviewApp.init/start/stop`. |
| HBox, VBox, GridPane, BorderPane, StackPane | `ReviewApp.start`, `buildHeader`, and `buildEditor` use all five layouts to compose the screen. |
| Label, TextField, Button, TextArea, CheckBox, ComboBox, TableView, ListView | `ReviewApp` uses these for search, editing, status, filtering, case results and recent activity. |
| Event handlers, listeners, input validation and feedback | `setOnAction` handles buttons, property listeners respond to selection and filters, `Task` imports off the JavaFX thread, and `Alert` reports validation errors or requests delete confirmation. |
